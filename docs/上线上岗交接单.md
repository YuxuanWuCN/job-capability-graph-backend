### 改后端代码的两种姿势

**A. 临时热修（30 秒，不重建）**

```bash
docker cp 新文件 job-graph-api-1:/app/<对应路径>
docker restart job-graph-api-1
```

⚠️ 热修只活在容器可写层里，容器被 `docker rm` 或镜像重建就会丢。`docker cp` 前务必确认源文件是完整版本（曾用 643 行的残缺 `resumes/service.py` 覆盖过容器，直接 `ImportError` 把 api 打死）。

**B. 正式重建（3~5 分钟，已验证可行）**

⚠️ **严禁直接 `docker compose up -d --build`**：2C4G 上四个容器同时在跑时构建会吃满内存导致整机假死（已发生过一次）。且纯配置/运行时参数变更（`compose.prod.yaml` 限额、Neo4j 内存参数、Worker 并发、`.env`）无需重建镜像，直接 `up -d --no-build` 即可。确需更新镜像时采用以下两种安全姿势之一：

1. **优先（零构建峰值）**：本地构建 → `docker save job-graph-backend:latest | gzip > image.tgz` → `workbench upload` 上传到服务器 → 服务器 `docker load -i image.tgz` → `docker compose -f compose.yaml -f deploy/compose.prod.yaml up -d --no-build`。
2. **备选（服务器现场构建，先停容器再建）**：

```bash
cd /opt/job-graph
docker compose -f compose.yaml -f deploy/compose.prod.yaml stop worker scheduler neo4j api
free -h   # 确认 available >= 1.5Gi
docker compose -f compose.yaml -f deploy/compose.prod.yaml build api
docker compose -f compose.yaml -f deploy/compose.prod.yaml up -d --no-build
```

3. **Top1 岗位可能反直觉**（数据分析简历的 top1 可能是"交叉研究"），因为教育维度得分高会托起总分。
4. **游客换设备 = 新身份**：游客数据绑在浏览器 cookie 上，换手机/清缓存后简历不在。需要长期保存请用邀请码注册正式账号。
