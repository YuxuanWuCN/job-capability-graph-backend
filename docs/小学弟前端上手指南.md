# 前端上手指南（给来帮忙改前端的同学）

> 你只需要改前端。**不用装后端、不用装数据库、不用碰服务器。**
> 本指南里的命令都已实测通过（2026-11-25）。

---

## 1. 三步跑起来

### 第 1 步：装 Node

装 **Node 22 LTS**（<https://nodejs.org>）。装完确认：

```bash
node -v    # 应该是 v22.x
npm -v
```

### 第 2 步：装依赖

在解压出来的目录里：

```bash
npm --prefix frontend ci
```

第一次装大概 2–5 分钟。如果卡住不动，换国内镜像再来一次：

```bash
npm config set registry https://registry.npmmirror.com
npm --prefix frontend ci
```

### 第 3 步：启动

```bash
npm --prefix frontend run dev:remote
```

浏览器打开 **<http://localhost:5173>**，就能看到真实数据的界面。

---

## 2. 为什么不用装后端

`dev:remote` 这个模式做了两件事：

1. 前端跑在你本机 5173 端口
2. 所有 `/api` 请求由 vite 转发到线上服务器 `8.153.183.119:8080`

转发发生在 Node 侧（服务器到服务器），所以**不受浏览器 CORS 限制**。你看到的是线上真实数据。

**已实测**：

| 请求 | 结果 |
|---|---|
| `http://localhost:5173/` | 200 |
| `http://localhost:5173/health/ready` | 200，postgres / redis / neo4j / llm 均 ok |
| `POST http://localhost:5173/api/v1/auth/guest` | 201，成功创建游客账号 |

> 注意：你在线上的操作是**真实写入**。别删数据、别批量提交垃圾简历。测注册/上传用明显的测试用户名。

### 两个模式的差别

| 命令 | 用途 | 需要本地后端吗 |
|---|---|---|
| `npm run dev:remote` | **推荐**，连线上数据 | 不需要 |
| `npm run dev` | 连本机 `localhost:8000` | 需要（你大概装不起来，别用） |

## 4. 改完怎么自检

```bash
# 类型检查 + 生产构建（必须过）
npm --prefix frontend run build

# lint
npm --prefix frontend run lint
```

`build` 过了才算改完。**TypeScript 报错不能留着**，CI 会卡住。

移动端问题记得用浏览器 DevTools 的设备模式看，至少测 390×844（iPhone 尺寸）。

## 5. 怎么把改动交回来

### 方式 A：走 Git（推荐）

负责人把你加成仓库协作者后：

```bash
git clone https://github.com/YuxuanWuCN/job-capability-graph-backend.git
cd job-capability-graph-backend
git checkout -b fix/你的问题描述
# 改代码
git add -A
git commit -m "fix(frontend): 一句话说清修了什么"
git push -u origin fix/你的问题描述
```

然后在 GitHub 上开 Pull Request。

> **推送失败提示 `Empty reply from server` / `SSL_read`？**
> 是本地代理的问题，不是仓库的问题。这一条命令绕过代理即可：
> ```bash
> git -c http.proxy= -c https.proxy= push -u origin fix/你的问题描述
> ```

### 方式 B：直接发文件

只发你**改过的那几个文件**，说清路径和改了什么。别发整个 `node_modules`。

## 6. 三条纪律

**① 只改 `frontend/` 下面的东西。**
不要动 `backend/`、`deploy/`、数据库、服务器配置。那些不是你的范围，改坏了会影响线上所有人。

**② 不要提交任何凭据。**
`.env`、私钥、API key、密码，一律不进 git。这个仓库是**公开**的。

**③ 不要试图登录服务器。**
你没有服务器权限，也不需要。前端开发全程在本机完成。

---

## 7. 卡住了怎么办

| 现象 | 原因 / 处理 |
|---|---|
| `npm ci` 卡住或超时 | 换 npmmirror 镜像（见 §1） |
| 端口 5173 被占用 | 配置里是 `strictPort: true`，会直接报错。关掉占用程序，或改 `vite.dev-remote.config.ts` 里的 port（同时改 `.env.remote` 里的端口） |
| 页面能开但接口 401 | 正常，先点游客登录 |
| 接口 502 / 超时 | 线上服务可能在重启，等一分钟再试；持续不行就找负责人 |
| `git push` 报 SSL / Empty reply | 本地代理问题，用 §5 的绕过命令 |
| 构建报 TypeScript 错 | 必须修掉，不能跳过 |

`health/ready` 里 `algorithm_service` 显示 `degraded` 是**已知状态**，不是你造成的，不用管。
