## 3. 学生怎么用（5 步）

1. 打开 http://8.153.183.119:8080/ ，点「使用邀请码注册」或用二维码直达；
2. 填邀请码 `a5b05f7e` + 用户名 + 姓名 + 密码（≥8 位），提交后自动登录；
3. 进「我的求职」( `/applicant` ) 上传简历（**PDF 或 DOCX，≤20MB**），等 15~40 秒解析；
4. 看解析出的能力画像，**逐项检查**（教育、经历、技能），不对就改，然后点「确认画像」；
5. 点「开始匹配」→ 得到岗位推荐（按分数排序、含维度得分与能力缺口）→ 点任一岗位「生成成长路径」。

> 第 4 步必须点「确认」，不确认匹配接口会返回 409 并提示「请先确认简历画像」。

## 8. 已知局限（评委问起来要能接住）

1. **岗位只有 4 个族**：J1 数字内容/人文、J2 数据/分析、J3 产品/管理、J4 交叉研究。这是能力框架的正式岗位族数量，不是坏了。台账里的 192 个新兴岗位在「新兴岗位」页（`/emerging`）作为**趋势洞察**呈现，要变成可匹配的正式岗位需要逐条走审核→发布（脚本化的工作，建议赛后做）。
2. **匹配分数偏低（当前 4 个岗位都是 low，总分 19~35）**：评分模型权重是「综合质量 0.45 + 知识基础 0.40 + 教育 0.15」，其中「知识基础」要求 33 项能力里被标为知识类的能力有证据，学生简历通常只覆盖技能类，于是这一项得 0，直接扣掉 40% 权重。**这是模型口径问题，不是学生不行**。话术：「当前版本偏保守，分数用于排序与看缺口，不是绝对水平」。
3. **Top1 岗位可能反直觉**：例如数据分析方向的学生，第一名可能是「J1 数字内容/人文」——因为该岗位的画像更容易被简历满足。以维度得分和缺口为主来解释，不要只念排名。
4. **算法服务（LGF）未部署**：`/health/ready` 里显示 degraded 是预期的，学生流程不依赖。
5. **无 HTTPS、无域名、无 ICP 备案**：靠 IP+8080 访问，属比赛临时方案；转正式对外要备案 + 证书。
6. **无自动备份、无监控告警**：出问题只能人工看日志。
7. **2核4G 内存偏紧**：常驻约 1.6G，剩 1.6G；同时上传 5 份以上简历（worker 并发 2）会排队变慢，不会崩。赛前别批量压测。

## 10. 故障速查

| 现象 | 先查 |
|---|---|
| 网页打不开 | 阿里云安全组是否放行 8080；`systemctl status nginx` |
| 能打开但一直转圈/接口 5xx | `docker compose logs -f api` |
| 简历一直「处理中」 | `docker compose logs -f worker`；`docker compose ps` 看 scheduler 是否 Up |
| 匹配报「当前没有正式图谱版本」 | 图谱版本丢了，重跑 `python scripts/bootstrap_capability_framework.py --admin-username admin` |
| 匹配报「请先确认简历画像」 | 学生没点确认，让他回第 4 步 |
| 成长路径报错/超时 | LLM key 或额度；`docker compose exec -T api python scripts/llm_smoke_check.py` |
| 注册报「邀请码不正确」 | `.env` 里的码与发出去的不一致（注意大小写） |
| 内存告警 | `docker stats --no-stream`；必要时 `docker compose restart worker` 释放 |
